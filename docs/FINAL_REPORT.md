# Первая версия трекера привычек: итог SDD

Дата завершения: 08.11.2026. Версия: v0.1.0. Результат принят по совокупности автоматических проверок и пользовательского подтверждения работы. Сценарии, которые не запускались, отдельно указаны в [матрице приёмки](ACCEPTANCE.md).

## Что получено

Десктопное приложение C++17 / Qt 6.9.1 Widgets для Windows 10, без авторизации, с PostgreSQL 18.6. Все семь обязательных возможностей реализованы: управление привычками, недельная таблица Пн–Вс, отметки без дубликатов, текущие серии, графики и итоги за 7/30 дней, встроенные цитаты, сохранение данных. Палитра розовая/бежевая; сегодня и серии выделены, выполнение отмечено зелёным.

Рабочая и тестовая базы раздельны: habit_tracker_sdd / habit_tracker_sdd_test, роль приложения не имеет административных прав. Пароли не опубликованы. Дополнительные функции за пределами согласованного списка не добавлялись.

## Как соблюдался Spec Driven Development

1. До кода обследованы установленные инструменты и доступность PostgreSQL; подготовлены README, SPEC, данные, экраны, приёмка и пять этапов.
2. По требованию пользователя добавлены визуальные макеты. Сначала согласованы поведение и макеты; C++/SQL-код появился после явного утверждения 06.11.2026.
3. Этапы реализовывались последовательно с предварительным планом, проверками, отчётом и сохранением в GitHub. Неудачные и пропущенные проверки не объявлялись пройденными.
4. Восстановление неизвестного пароля администратора вынесено в отдельный согласованный план. Исходные правила аутентификации восстановлены с проверкой контрольной суммы; базы других проектов не удалялись.
5. На завершении добавлены проверка сохранения между независимыми процессами, масштабирование Qt и матрица соответствия требованиям.

История сохраняется в [GitHub](https://github.com/novikovka/habit-tracker-sdd). Метки stage-1…stage-5 и v0.1.0 позволяют воспроизвести промежуточные версии. Начальный коммит спецификации — 86b0c80; код этапов — 00d0897/a1302b6, 6e82e3e, 581430b, 49639fb. Последняя версия приложения не меняет функциональное поведение этапа 4; этап 5 добавляет проверку и документацию.

## Ошибки и вмешательства

| Причина | Что произошло и как исправлено |
| --- | --- |
| Среда исполнения инструментов | Sandbox helper не запускал команды; использованы разрешённые запуски вне него. CIM сначала отказал в доступе |
| Git/GitHub | Не было репозитория и gh; Desktop/browser automation не стартовала. Репозиторий создан через GitHub API с сохранённым подключением, без вывода токена; ownership Git обработан точечным safe.directory |
| Qt moc / путь | moc не создавал файлы по пути с кириллицей; временный ASCII-диск subst решил проблему без переноса исходников |
| PowerShell | UTF-8 без BOM читался неверно в PS 5.1; добавлен BOM. Несовместимое свойство .NET проверено и заменено передачей байтов через stdin |
| PostgreSQL | Административный пароль оказался неизвестен; интеграционные проверки сначала упали на входе. Исправлена диагностика, проведены независимые проверки временного сервера, затем разрешённое восстановление доступа |
| Визуальные/клавиатурные дефекты | Исправлены дублирующая цифра серии, потеря фокуса клетки, интерпретация подсказки как HTML, перераскладка статистики и лишние полосы прокрутки |
| Служебные правки | Несколько apply_patch отклонены из-за контекста/повторного пути; исправлены без частичного изменения исходников |

CMake сообщает об отсутствующих WrapVulkanHeaders, но сборка Qt Widgets и все проверки успешны. Это некритичное сообщение не скрывается и не считается ошибкой приложения.

Ручные действия пользователя: согласование спецификации/макетов; разрешение команд вне sandbox; попытки setup-database.ps1 с паролем и передача текста ошибок; явное разрешение сброса postgres; закрытие приложения перед обновлением exe; работа с привычкой/отметками; подтверждение перезапуска, переименования/удаления и статистики. Длительности этих действий неизвестны.

## Проверки и принятие

- Итоговая сборка на Windows 10 build 19045 выполнена; CTest 10/10, ноль ошибок и пропусков.
- 61 Qt Test PASS включает служебные init/cleanup. Дополнительно выполнены шесть UI-запусков при Qt scale 125% и 150%.
- Контрольные суммы спецификации (5 и 7), календарные края, 70-дневная серия, идемпотентность, каскадное удаление, ошибка/восстановление подключения и сохранение между процессами подтверждены.
- Пользователь сообщил «всё работает» и подтвердил три проверки: перезапуск с сохранением, переименование/удаление, статистика.
- Исходный 11-пунктовый ручной сценарий не выдан за полностью выполненный вручную: автоматические эквиваленты и пользовательские проверки разделены в ACCEPTANCE.md.

Испытания на чистом другом ПК, реальная смена часов/часового пояса Windows, сетевой обрыв в момент записи, длительная нагрузка и полный ручной Tab-проход не выполнялись. Масштабирование проверено окружением Qt, а не изменением системного масштаба. Автономный установщик не создавался; запуск в обследованной среде описан в RUN.md.

## Что можно сравнить со вторым подходом

У этой реализации есть заранее согласованный контракт поведения, макеты, последовательные версии и воспроизводимые проверки. Можно сопоставлять затраты на спецификацию, число уточнений и исправлений, совпадение результата с требованиями и готовность к приёмке. Нельзя делать вывод, что SDD быстрее или качественнее другого подхода: вторая реализация ещё не выполнялась. Ей нужна отдельная база на том же сервере и тот же набор исходных требований/приёмки, чтобы различие в окружении не стало скрытой причиной результата.
