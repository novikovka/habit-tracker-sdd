# Запуск и повторная сборка v0.1.0

## На текущем компьютере

Рабочая папка разработки: `D:\МАГИСТРАТУРА\Визуальное программирование\habit-tracker-sdd`. Копия на рабочем столе — отдельный Git-клон; исходники синхронизируются через GitHub, артефакты build не копируются. Для сборки второй копии нужно выполнить build.ps1 именно в ней. Одновременно две сборки с одной буквой H: не запускаются.

Базы habit_tracker_sdd и habit_tracker_sdd_test и роль habit_tracker_sdd_app уже настроены. Повторная настройка или восстановление пароля сейчас не требуется.

В PowerShell из корня проекта:

```powershell
.\scripts\run.ps1
```

Введите пароль роли приложения локально. При запуске откроется текущая неделя. Привычки и отметки сохраняются в PostgreSQL. Закрытие окна не останавливает сервер базы данных.

Конфигурация без пароля: `%LOCALAPPDATA%\HabitTrackerSDD\connection.ini`. Образец — config/connection.example.ini. Если нужен другой файл, задайте HABIT_TRACKER_CONFIG. Для этой версии допускается локальный сервер; перед использованием удалённого подключения нужно отдельно согласовать TLS.

## Сборка исходников

```powershell
.\scripts\build.ps1 -Test
```

Исполняемый файл: `build\qt\habit_tracker.exe`. Если приложение открыто, перед сборкой закройте его: Windows блокирует замену исполняемого файла.

Скрипты по умолчанию используют Qt 6.9.1 / MinGW 13.1.0 из D:\Qt, CMake 3.30.5, Ninja 1.12.1 и libpq из PostgreSQL 18. Другие пути передаются -QtRoot и -PostgresBin. Qt, MinGW и библиотеки должны относиться к одному совместимому комплекту.

Для обхода ошибки Qt moc с кириллицей build.ps1 временно подключает H: к папке проекта и снимает это подключение в finally. Если H: занят, можно указать другую свободную букву -BuildDrive; при смене буквы для существующей сборки каталог build/qt предварительно переименовывается для чистого CMake-кэша. Системный PATH не меняется. PowerShell-скрипты используют UTF-8 с BOM для Windows PowerShell 5.1.

Один exe не является автономным дистрибутивом: ему нужны DLL Qt, QPSQL, libpq и их зависимости. scripts/run.ps1 задаёт пути к ним на время работы процесса и восстанавливает окружение после выхода. Установка/проверка на чистом Windows-компьютере не выполнялась.

## Интеграционные проверки

build.ps1 -Test пропускает проверки реальной БД. Полная проверка выполняется так:

```powershell
$secure = Read-Host 'Пароль роли приложения' -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
$previousPassword = $env:HABIT_TRACKER_DB_PASSWORD
try {
    $env:HABIT_TRACKER_DB_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
    .\scripts\build.ps1 -Integration
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
    $secure.Dispose()
    $env:HABIT_TRACKER_DB_PASSWORD = $previousPassword
}
```

Интеграционные тесты принудительно работают только с habit_tracker_sdd_test. Отчёты сохраняются в build/qt/*-results.txt. PersistenceProcessTest запускает два отдельных тестовых процесса; это не скрытый режим пользовательского exe. Подробные результаты — [ACCEPTANCE.md](ACCEPTANCE.md).

## Если нет соединения

Проверить, что PostgreSQL работает, порт/роль/имя базы в конфигурации верны и пароль введён для habit_tracker_sdd_app. Затем нажать «Повторить». Не добавляйте пароль в INI: приложение его отклоняет. Если нужен новый сервер, первоначальная подготовка описана в STAGE1.md и выполняется setup-database.ps1 с действующим административным входом. Разовый план POSTGRES_RECOVERY.md уже выполнен, он не является обычной процедурой запуска.

## Для второго проекта сравнения

Использовать другую базу на том же сервере и собственную конфигурацию. Имена habit_tracker_sdd и habit_tracker_sdd_test относятся к этой реализации. Общие системные Qt/компилятор/PostgreSQL можно оставить, чтобы сравнение не зависело от повторной установки окружения. Привычки из базы первого проекта не копировались в другой проект.
